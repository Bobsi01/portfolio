Comprehensive VPS Security ChecklistThis document provides a complete, tiered checklist for securing a Virtual Private Server (VPS), covering everything from initial setup to advanced kernel hardening.Phase 1: Standard Baseline Security1. User & Access Management[ ] Create a non-root sudo user: Never execute daily operations as root. Create a dedicated administrative account.[ ] Enforce SSH key authentication: Generate an ED25519 or RSA-4096 key pair. Disable password-based logins by setting PasswordAuthentication no in /etc/ssh/sshd_config.[ ] Disable root SSH login: Set PermitRootLogin no in the SSH configuration to force attackers to guess both the username and the private key.[ ] Change the default SSH port: Move SSH from port 22 to a non-standard port (e.g., between 1024 and 65535) to evade automated scanner bots.[ ] Set SSH timeouts: Configure ClientAliveInterval (e.g., 300 seconds) and ClientAliveCountMax (e.g., 2) to automatically disconnect idle sessions.2. Network & Firewall Configuration[ ] Allow essential incoming ports first: Explicitly open your custom SSH port, 80 (HTTP), and 443 (HTTPS) before enabling the firewall to prevent locking yourself out.[ ] Configure default firewall rules: Set default policies to deny all incoming traffic and allow all outgoing traffic using UFW, firewalld, or iptables.[ ] Bind internal services to localhost: Ensure backend databases (e.g., PostgreSQL, MariaDB) and cache services bind strictly to 127.0.0.1 so they are not exposed to the public internet.[ ] Disable IPv6 (if unused): Prevent traffic from bypassing IPv4 firewall rules by disabling IPv6 at the kernel level if your infrastructure does not require it.3. Intrusion Prevention & Auditing[ ] Install Fail2Ban or CrowdSec: Automatically ban IP addresses that exhibit malicious behavior, such as repeated failed SSH login attempts or web application probes.[ ] Configure time synchronization (NTP): Ensure server time is perfectly synced via NTP for accurate log auditing and valid cryptographic operations.[ ] Secure shared memory: Secure /run/shm by mounting it as noexec and nosuid in /etc/fstab to prevent malicious scripts from executing in memory.4. Updates & Maintenance[ ] Enable automatic security updates: Configure unattended-upgrades (Debian/Ubuntu) or dnf-automatic (RHEL/CentOS) to apply critical security patches automatically.[ ] Audit open ports: Regularly run ss -tulpn or netstat -tulpn to verify that only intended services are listening on external interfaces.[ ] Remove unused packages: Uninstall unnecessary software, modules, and legacy dependencies to minimize the available attack surface.5. Application-Level Security[ ] Run services as dedicated users: Run web servers, application runtimes, and background processes using isolated, unprivileged system accounts—never as root.[ ] Restrict file permissions: Enforce the principle of least privilege. Directories should generally be 755 and files 644, strictly owned by the service user requiring access.[ ] Implement remote backups: Schedule automated data and configuration backups to an offsite location. Test the restoration process to verify data integrity.Phase 2: Advanced Hardening6. Advanced Authentication[ ] Implement SSH Two-Factor Authentication (2FA): Integrate a PAM module (e.g., Google Authenticator libpam-google-authenticator) to require a time-based code in addition to your SSH key.7. Kernel & Network Hardening[ ] Tune sysctl.conf: Modify kernel parameters in /etc/sysctl.conf to mitigate network attacks.[ ] Enable TCP SYN cookies (net.ipv4.tcp_syncookies = 1).[ ] Disable IP forwarding if not acting as a router (net.ipv4.ip_forward = 0).[ ] Disable ICMP redirects (net.ipv4.conf.all.accept_redirects = 0).[ ] Ignore ICMP broadcast requests (net.ipv4.icmp_echo_ignore_broadcasts = 1).8. Mandatory Access Control (MAC)[ ] Enforce AppArmor or SELinux: Do not disable these modules. Keep them in enforcing mode to restrict the capabilities of compromised applications, even if they run as root.9. System Integrity & Deep Auditing[ ] Install an intrusion detection system (HIDS): Deploy AIDE or Tripwire to monitor and alert on unauthorized changes to critical system files.[ ] Scan for rootkits: Schedule regular scans using rkhunter or chkrootkit to detect hidden malicious processes.[ ] Deploy auditd: Track specific system calls, file access, and executed commands for forensic analysis.10. Edge Protection[ ] Use a Web Application Firewall (WAF): Route HTTP/HTTPS traffic through a proxy (e.g., Cloudflare) or install ModSecurity to filter out SQL injection, XSS, and zero-day exploits before they hit your application runtime.[ ] Hide the origin IP: If using a WAF or CDN, configure your firewall to drop all port 80/443 traffic that does not originate from the CDN's known IP ranges.
